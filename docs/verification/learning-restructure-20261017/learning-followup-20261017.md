## 5. Provider 오류 조사

- 실제 경로: LessonPage → registry lazy loader → Lesson11/Lesson12 → StudyProvider → StudySteps. 두 차시의 7개 STEP은 Provider 안에 있으며 조건부 Provider 누락을 발견하지 못했습니다.
- `StudyActivity.tsx`의 `useStudy`는 `useContext`가 null일 때 해당 오류를 던집니다. 관련 6개 import는 같은 모듈로 연결됩니다.
- Context·컴포넌트·일반 함수가 같은 모듈에서 export됩니다. 설치된 Vite React 플러그인의 Fast Refresh 경계 무효화 경로를 확인하여 HMR 중 모듈 재평가 가능성은 확인했지만, 당시 오류 stack/HMR 로그가 없어 실제 원인으로 확정할 수 없습니다.
- 이번 정상 직접 진입·STEP 왕복·답안 제출·새로고침·완료 후 재진입은 정상. 마지막 브라우저 warn/error 로그는 빈 배열이었습니다. 소스 변경을 만들어 과거 HMR 오류를 강제로 재현하지 않았습니다.
- 따라서 Provider 코드는 추측으로 수정하지 않았으며, ‘현재 일반 경로 미재현 / 과거 HMR 원인 미확정’으로 남깁니다.

#### MNIST 실제 취소·재실행 기록

1. 기존 실험 기록 두 개를 UI 표에서 확인했습니다. Train 2000/Epoch 5 실행 중 Epoch 5의 20/63 batch(전체 272/315, 86%)를 관찰한 뒤 **학습 취소**를 눌렀습니다.
2. 취소 처리 후 277/315(87%)에 정지하고 ‘학습 취소됨’ 및 다음 시작 시 진행률이 0부터 시작한다는 안내가 표시됐습니다. 시작 버튼이 다시 활성화되고 취소 버튼은 사라졌습니다. 취소 실행은 실험 기록에 추가되지 않았으며 기존 두 기록은 동일했습니다.
3. Train 500/간단한 모델/Epoch 1/Batch 32로 재실행했습니다. 1/16(6%)부터 새 진행을 관찰했고, 16/16 종료 후 loss **2.1706**, 훈련 정확도 **25.40%**, 시간 **0.63초**를 확인했습니다.
4. 실험 기록은 기존 2개 + 새 실행 1개로 총 3개였습니다. 새 기록의 조건·지표·시간이 결과 화면과 일치했고, 취소된 2000/5 실행의 완료 기록은 생기지 않았습니다. 이후 대기·재진입·새로고침에서도 3개와 기존 두 기록을 확인했습니다. 관찰한 시간 내 취소 실행의 뒤늦은 결과 덮어쓰기는 없었습니다.
