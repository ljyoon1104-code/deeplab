### 캡처 신뢰성과 환경 이력

- **ENV-01 / 이전 실행 차단:** 상위 경로 접근 거부로 개발 서버 실행이 실패했으나 사용자가 실행한 주소로 해결했다. 권한·실행 정책·Git 설정을 바꾸지 않았다.
- **ENV-02 / 이전 검사:** 캡처 실패, 직전 STEP 반환, 검정·흰 영역이 발생했다. [이전 불일치 캡처](ui-audit-stage1/ENV-02-stale-resize-capture.jpg)는 환경 제한 증거로만 보존하고 앱 결함·정상 판정에 사용하지 않았다.
- 이번 이어가기에서는 화면 준비를 확인한 후 캡처했다. Lesson 04 이동 중 대상 요소를 찾지 못한 조작은 증거에서 제외하고 STEP 버튼으로 현재 상태를 확인했다. 같은 실패를 반복하지 않았다.
- 빠르게 연속 누른 설명 버튼이 예상 횟수만큼 이동하지 않은 경우 실제 표시된 단계 번호를 기준으로 기록했다. 예: L09 모바일 중간 캡처는 **2/6**, 데스크톱 중간은 **4/6**이다. 마지막 6/6과 혼동하지 않는다.
- 긴 전체 페이지 캡처의 sticky 헤더가 이미지 중간에 합성되는 현상은 실제 화면의 영구 가림으로 판정하지 않았다. L11 데스크톱 최종 캡처의 중간 헤더도 여기에 해당한다.
- 키보드 포커스는 대표 버튼에서 확인했다. 전환 중간 프레임, 실제 터치 기기, `prefers-reduced-motion` 설정 변경은 도구에서 확인하지 못했다.

## 3. 문제 목록과 실제 증거

높음 우선순위의 레이아웃 진행 차단은 확정하지 않았다. 아래 우선순위는 실제 읽기·조작 영향에 근거하며 코드 원인은 변경 없이 확인한 **후보**다.

### UI-01 / 낮음 — 모바일 STEP 7 하단 버튼의 한 글자 줄바꿈

- **위치·크기:** L01~12 공통 S7, M 360×800. L01~02는 이전 결과, L03~12는 이번 결과.
- **재현:** 필수 활동 미완료 상태로 S7 이동 → 하단의 중앙 미완료 안내와 양쪽 버튼 확인.
- **기대 / 실제:** ‘이전·완료’가 자연스럽게 읽혀야 하나 ‘이/전·완/료’로 줄바꿈된다.
- **조작 영향:** L04 표본에서 이전 약 78.1×62px, 완료 약 76.1×60px로 44px 이상. L06 S7의 ‘이전’으로 S6 이동 성공. 비활성 완료는 미충족 조건에 따른 상태다. **터치 영역 부족·진행 차단으로 단정하지 않는다.**
- **증거:** [기존 L01 전체 맥락의 맨 아래](ui-audit-stage1/L01-S07-mobile.jpg).
- **원인 후보:** `src/components/BottomLessonNavigation.tsx`의 한 행 flex에서 중앙 안내와 버튼이 공간을 나눔. 연결된 `ui/Button.tsx`에는 가로 축소·줄바꿈 방지가 없음.
- **최소 방향:** 하단 내비게이션 안에서만 버튼 폭·줄바꿈 및 안내 배치를 조정.
- **재검증:** D/M에서 미완료·완료 가능·완료 후 상태, 이전 이동·Tab 포커스. 완료 가능 상태는 아직 미확인.

### UI-02 / 중간 — 좁은 데스크톱 카드 안에서 가로 흐름도가 압축됨

- **위치·크기:** L04 S5의 세 출력 사례 카드, L07 S7 INPUT 흐름. D 1440×900.
- **재현:** 해당 STEP 초기 화면 → 출력 사례 또는 INPUT 흐름 카드 확인.
- **기대 / 실제:** 노드 문구와 화살표가 각각 구별되어야 하나 한글이 한 글자씩 세로로 늘어나고, Sigmoid·Softmax·28×28·INPUT 등의 문자열이 노드 폭을 넘는다.
- **영향:** 출력 형태와 함수/전처리 순서를 비교하기 어렵다. M의 세로 흐름은 같은 압축이 없었다.
- **증거:** [L04 출력 사례](ui-audit-stage1/R2-L04-S05-desktop-overlap.jpg), [L07 INPUT](ui-audit-stage1/R2-L07-S07-desktop-narrow-flow.jpg).
- **원인 후보:** `src/lessons/lesson04/NeuralNetworkDiagram.tsx`의 SimpleFlow, `src/lessons/lesson07/Lesson07Steps.tsx:43`의 FlowChain. `md:grid-flow-col md:auto-cols-fr`가 실제 카드 폭과 무관하게 가로 배치를 선택하고 화살표도 grid 열을 차지한다.
- **최소 방향:** 좁은 카드에서만 세로/줄바꿈 배치 또는 노드·화살표 열 폭 조정. 계산·MNIST 흐름은 그대로 보존.
- **재검증:** L04 S5 세 사례, L07 S7 기본/세부/INPUT/TARGET 흐름을 D/M에서 비교.

### UI-03 / 중간 — 2–2–1 그림의 출력층 명칭을 연결선이 통과

### UI-04 / 중간 — 예측 차이 입력 카드의 오른쪽 잘림

- **위치·크기:** L05 S2 사례 A/B, M 360×800.

## 4. 정상 관찰과 미확인의 경계

### 확인한 표시·조작

- 이번 캡처 상태에서 문서 전체 scrollWidth와 clientWidth가 같았다. **부모 영역 안에서 잘리는 UI-04 같은 문제까지 없다는 뜻은 아니다.**
- STEP 내비게이션과 일부 표의 내부 가로 스크롤은 의도된 구조로 구분했다. 처음에 모든 STEP 카드가 보이지 않는 것을 결함으로 등록하지 않았다.
- 신경망·GAN·RNN·클래스 비교의 주요 두 열은 모바일에서 세로로 바뀌었다. 문제로 기록한 요소 외에 확인한 전환의 카드끼리 가림은 발견하지 못했다.
- L11 설명 ‘다음’에서 Tab으로 ‘다시 보기’에 이동했을 때 `:focus-visible`이 적용되고 3px 윤곽선이 표시됐다. 이전 검사 L02의 Enter 전환 결과도 유지한다.
- 설명 이동·이전·다시 보기와 실제 활동 제출/학습 버튼의 이름이 구별된다. 설명 다시 보기로 결과가 중복되는 현상은 확인한 대표 장면에서 관찰하지 못했다.
- 모든 STEP/차시 완료를 누르지 않았다. 일부 활동 선택과 단순 뉴런 업데이트는 결과 레이아웃을 열기 위한 일반 UI 조작이다.
