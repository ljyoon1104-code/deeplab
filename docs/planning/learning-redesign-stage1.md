## A. 전체 설계 원칙

### A1. 목표와 난이도를 유지하는 개선

1. 3개 모듈, 12차시, 차시별 7 STEP, 기존 계산·응용·종합 과제를 보존한다.
2. 어렵다는 이유로 독립 계산이나 근거 판단을 설명 읽기로 바꾸지 않는다. 설명이 없어서 어렵다면 **기존 활동 앞**을 보완한다.
3. 새 개념은 이름뿐 아니라 의미·목적·사용 위치를 짧게 설명한다. “모델”, “가중합”, “벡터”처럼 뒤 활동이 의존하는 말은 오답 해설에서 처음 등장하지 않게 한다.
4. 교과서의 기본 과정과 앱의 세부 조작은 같은 과정의 확대임을 명시한다. 서로 다른 절차 두 개를 외우게 하지 않는다.
5. 원-핫과 임베딩은 표현 방법의 비교이고, RNN·Attention·Transformer는 모델·아이디어·구조의 관계이다. 모두를 필수 순차 실행 단계로 그리지 않는다.
6. 동일 문항을 반복 제출하게 하거나 설명 시청 횟수를 채우게 하는 새 조건은 만들지 않는다. 기존 관찰·제출 조건은 이번 설계에서 임의로 삭제하지 않는다.

### A2. 두 학습 틀의 적용

**유의미 수용학습:** 기존 개념을 먼저 불러오고 전체 관계를 제시한 뒤 세부로 들어간다. 예를 들어 Lesson 04는 “Lesson 02의 출력이 다음 뉴런의 입력이 된다”는 관계를 먼저 보여 준다. 각 층 이름만 나열하는 목차로 대신하지 않는다.

**문제해결학습:** 목표→조건→선택·실행→결과 근거→수정의 기회를 기존 활동 안에 둔다. Lesson 02의 목표 출력 설계, Lesson 01의 방법과 근거 선택, Lesson 09의 독립 합성곱, Lesson 08의 실제 실험 비교를 그대로 활용한다. 모든 활동에 서술형을 추가하지 않는다.

### A3. 계산과 적용의 깊이

| 계산·활동 | 기존 깊이 유지 | 보완 방식 |
|---|---|---|
| 퍼셉트론·계단·렐루·작은 신경망 | 곱셈·합산·편향, 중간값, 독립 계산, 목표 출력 설계 | 수식과 그림의 같은 입력·연결·출력을 대응시킨다. |
| 오차·MSE | 차이·제곱·평균, 오차 상쇄, 모델 비교 | 무엇을 비교하는 계산인지 먼저 제시한다. |
| 시그모이드·소프트맥스·BCEE·CCEE | 실제 함수 결과의 변화와 의미 해석 | 지수·로그 손계산은 추가하지 않는다. |
| 역전파 | 실제 BCE 업데이트·반복 결과 해석 | 미분 과제 대신 고정값·수정값·다시 계산되는 값의 연결을 보인다. |
| MNIST | 실제 좌표·차원 변환·정규화·원-핫·학습·평가 | 설명만 보완하고 수치·상태·엔진을 그대로 읽는다. |
| 합성곱·풀링 | 안내·독립 계산, 크기·최댓값·필터 비교 | 현재 계산 함수가 만든 중간 결과를 위치와 대응시킨다. |
| 텍스트 | 양방향 인덱스, 원-핫, 빈도·비율, 문맥·방법 선택 | 숫자 표현의 목적과 한계를 같은 단어·문장으로 연결한다. |
| 문장 생성 | 빈도 합·비율, 후보 비교, 새 문맥 | 고정 교육 예시임을 유지하고 실제 Attention·LLM 계산을 추가하지 않는다. |

값 변경, 목표 조건 조절, 상황별 방법 선택, 결과 비교, 오류 수정, 실제 실험이라는 기존 적용 수준을 모두 남긴다. 계산 목적→완성 풀이→부분 풀이→독립 계산→해석은 **현재 STEP들에 걸쳐 연결**하며 매번 다섯 활동을 새로 만들지 않는다.

### A4. 공통 시각화·완료·저장 계약

- 도입 설명은 상시 텍스트로 제공한다. 툴팁·접힌 도움말·정답 해설은 보조 수단이다.
- 강조는 색뿐 아니라 번호·테두리·현재 값·짧은 문장으로 표현한다.
- 설명용 진행은 학생의 이전·다음·다시 보기로 움직이고 자동 재생하지 않는다. 각 장면에서 정지한다. 이동 효과가 있더라도 입력·채점을 지연시키지 않는다.
- 움직임 줄이기 환경에서는 이동 없이 같은 테두리·번호·값·문장이 즉시 바뀐다. 현재 공통 피드백·키보드 조작·모바일 배치를 재사용한다.
- 설명용 커서는 지역 표시 상태로만 둔다. 정답, 관찰 기록, 모델 업데이트, STEP 완료 함수를 호출하지 않는다. 다시 보기는 풀이 화면만 되돌리고 학생 답·학습 모델·활동 기록을 지우지 않는다.
- 기존 완료 조건, STEP ID, 저장 키, 완료 버전은 유지한다. 신규 설명이나 그림을 봤다는 이유로 완료하지 않는다.
- 모든 차시 래퍼가 STEP 7에 앞 STEP 1~6 완료 여부를 전달하는 현재 연결을 보존한다. 각 차시 고유 필수 계산·정답·실험 조건도 유지한다. Lesson 08의 실제 결과 해석을 고정 수치 정답 퀴즈로 바꾸지 않는다.
- 중앙 진행도 키는 deep-learning-lab:progress:v1, 완료 버전 키는 deep-learning-lab:completion-versions:v1이다. 현재 명시된 Lesson 01~07·09~12의 버전 2와 Lesson 08의 기존 처리 모두 그대로 둔다. 전체 초기화·일괄 버전 상향 계획은 없다.
- 저장 문자열이 식별자로도 쓰이는 경우 표시 문구만 별도 대응한다. 예: CNN 흐름의 flatten·완전연결층, RNN 상태 답안 문자열. 기존 저장 값을 일괄 치환하지 않는다.

8개 모두 **설명용 수동 진행**이다. 시작/이전/다음/다시 보기 버튼을 사용하고 각 장면에서 멈춘다. 자동 재생을 넣지 않아 별도 일시정지 타이머가 필요 없다. ‘다시 보기’는 설명용 커서만 첫 장면으로 이동한다. 기존 정답·모델·관찰 기록은 건드리지 않는다.

현재 단계 제목과 값은 상시 텍스트로 제공하고 필요한 변경만 aria-live로 알린다. 버튼은 키보드·터치로 조작, 드래그는 불필요하다. 360px에서는 세로 배치·줄바꿈을 사용한다. reduced-motion에서는 이동·흔들림 없이 강조 테두리와 문장을 즉시 변경한다. 긴 설명을 Tooltip에만 넣지 않는다.

### V1. 퍼셉트론 한 번의 계산

- 위치: Lesson02 S2 완성 풀이. 시작: ‘풀이 한 단계씩 보기’.
- ① 입력 두 개를 표시: “모델이 받은 값입니다.”
- ② 대응 입력과 선의 가중치를 같은 번호로 강조: “연결별로 입력에 가중치를 곱합니다.”
- ③ 두 곱의 합: “모든 곱을 더합니다.”
- ④ 편향과 z: “편향을 더한 값이 가중합입니다.”
- ⑤ 계단 함수와 출력: “z가 음수이므로 0입니다. 가중합 -1과 출력 0은 다른 값입니다.”
- 데이터: 현재 완성 예제의 calculatePerceptronN 결과. 화면용 -1·0을 별도 결과 배열로 하드코딩하지 않는다.
- (8,6) 부분 풀이에서는 현재 제출 전 공개 범위를 유지한다. 설명 재생이 빈칸을 채우거나 정답 플래그를 설정하지 않는다.

### V2. 2입력–2은닉–1출력 경로

- 위치: Lesson04 S3, S4에는 범례만 재사용.
- 시작: H1 경로 보기. 입력 두 원과 H1으로 들어가는 두 선만 두꺼워지고, 수식의 두 항에 동일 번호를 표시한다.
- 다음: H1 가중합→렐루 출력. 그 출력이 출력층으로 연결되는 선 시작점에 남는다. 설명: “이 값은 다음 층에서 입력으로 쓰입니다.”
- 다음: H2 경로→두 은닉 출력→출력층 계산. 안내 예제에서 이미 공개된 값만 표시한다.
- 선은 가중치, 뉴런 옆 값은 편향, 원 아래 값은 활성화 후 출력이라는 범례를 고정한다. 일반 장식 선을 정확한 수치 연결로 재사용하지 않는다.
- 데이터: forwardTinyNetwork 결과와 config. S4 미제출 필드는 빈 값/물음표, 정답 공개는 기존 피드백 시점 유지.
- 계산식·required 인덱스·isClose 판정·학습 설정 변화 없음.

### V3. 두 배열의 같은 열 비교

- 위치: Lesson05 S6, 현재 세 클래스 표.
- 시작: ‘정답과 예측을 나란히 보기’. Setosa·Versicolor·Virginica 머리글을 두 배열 공통으로 보여 준다.
- 다음: 레이블 Virginica→원-핫 세 번째1. “정답이 있는 위치입니다.”
- 다음: 같은 열의 예측 .84. “이 클래스에 모델이 부여했다고 가정한 확률입니다.”
- 다음: 현재 loss 계산 결과 약 .17. “CCEE는 이 정답 위치의 예측 확률을 이용해 오차를 계산합니다.”
- 다른 preset 선택 시 기존 확률·계산값을 사용해 비교한다. 로직에 새 preset을 추가하지 않는다.
- 0과1 표시와 확률을 같은 종류의 값으로 부르지 않으며, 로그 계산을 학생 입력칸으로 만들지 않는다.

### V4. 실제 업데이트의 전후 관계

- 위치: Lesson06 S5의 전후 표 아래, S6는 기존 기록 선택 시 재사용 가능.
- 시작은 실제 ‘1회 학습’ 후에 생성된 기록의 ‘변화 따라보기’. 안내 설명은 버튼 전에도 상시 제공한다.
- ① 고정된 x1·x2·y에 자물쇠 대신 ‘고정’ 텍스트와 테두리.
- ② 수정 전 w·b, 계산된 예측·오차 강조.
- ③ 실제 업데이트 후 바뀐 w·b 칸만 강조: “오차 정보를 이용해 값을 수정했습니다.”
- ④ 같은 입력으로 새 z·예측·오차 칸 강조: “수정한 값으로 다시 순전파했습니다.”
- 역방향 강조는 오차 정보, 순방향 강조는 계산값으로 라벨을 구별한다.
- 다시 보기는 기록을 읽기만 하고 update·train 함수를 호출하지 않는다. 실제 반복 그래프에 가짜 보간 데이터 추가 없음.

### V5. 합성곱 입력 창과 출력 주소

- 위치: Lesson09 S4 안내 위치, S5 교과서 예제.
- 시작: 기존 위치 선택 버튼. 선택 입력 창과 해당 특징 맵 칸을 동일 번호로 표시.
- 다음: 입력칸·필터칸의 같은 위치를 차례로 강조하며 실제 곱을 기존 풀이 목록에서 밝힌다.
- 다음: 곱의 합을 해당 출력칸에 연결. 학생 독립 위치는 제출 전 합을 자동 공개하지 않는다.
- 이전/다음 위치는 기존 네 위치 선택을 이용한다. ‘풀이 다시 보기’는 선택 위치의 강조만 초기화하며 관찰 기록을 지우지 않는다.
- 데이터: convolveAt·convolve2D의 기존 결과. 작은 연습과 교과서 예제 모두 결과가 같더라도 입력·필터 크기를 제목에 항상 표시.
- 두 번째 필터 비교는 같은 입력을 유지한 채 기존 계산 결과를 병치한다. 고정 필터는 원리 설명용이며 실제 CNN에서는 학습한다는 기존 설명 유지.

### V6. 숫자 표현의 비교

- 위치: Lesson11 S4–S5 연결.
- 시작: 기존 단어 선택. 먼저 원-핫에서 인덱스·1의 위치·벡터 길이를 연결한다.
- 다음: 비교 패널로 이동하여 ‘원-핫: 단어 목록 크기만큼의 칸’과 ‘교육용 임베딩: 좌표 두 개’를 나란히 강조. 변환 화살표를 두 표현 사이에 그리지 않는다.
- 다음: 기존 친구·우정·냉장고 좌표에서 가까움/멀어짐을 강조. 두 패널이 같은 단어 집합을 가진 것처럼 가장하지 않고, “원-핫 예문 단어”와 “의미 거리 비교용 단어”라는 기존 서로 다른 예시임을 명시한다.
- 설명: “차원은 한 표현에 쓰는 숫자의 개수입니다. 이 2차원 그림은 실제 모델 좌표가 아닌 설명용 예입니다.”
- 원-핫은 createOneHot, 임베딩은 기존 고정 좌표에서 읽는다. 임베딩을 새로 학습하거나 의미에 맞추어 좌표를 변경하지 않는다.
- 기존 상대 거리·표현 방식·한계 문제는 유지하고 설명 전환 횟수를 완료 조건으로 넣지 않는다.

### V7. RNN의 이전 정보 재사용

- 위치: Lesson12 S2. 현재 ‘다음 단어’와 기억 선택을 유지.
- 다음 단어를 처리할 때 **지금까지 읽은 문맥**, **현재 단어**, **갱신되는 상태**를 동시에 표시한다.
- 예: ‘못’ 뒤 ‘부르지’를 처리할 때 앞의 ‘너는·노래를·못’이 이전 문맥 영역에 남고 현재 ‘부르지’와 함께 RNN 박스를 가리킨다. 마지막 ‘않아’에서 앞 부정 표현과 함께 뜻을 살펴봐야 함을 강조한다.
- “앞 단어를 글자 그대로 모두 저장하는 실제 내부 구조를 보여 주는 것은 아닙니다. 상태가 이전 정보를 활용한다는 설명용 표시입니다.” 상시 안내.
- 현재 문항의 state 문자열은 ‘이번 단계에서 더해지는 정보’로 표시해 기존 정답·저장 답과 충돌하지 않게 한다. 상태 전체가 이 짧은 문장 하나뿐이라는 인상을 줄인다.
- 기존 완료된 장면의 ‘이전 설명/다시 보기’는 별도 지역 커서로 읽기만 한다. 원래 currentIndex·memoryAnswers·viewed를 되돌리거나 조작 횟수를 늘리지 않는다.
- 정답은 보여 주는 누적 문맥만 읽었다고 자동 입력하지 않는다. 학생의 기존 상태 선택은 유지한다.

### V8. 다음 단어가 새 문맥에 합쳐지는 과정

- 위치: Lesson12 S6. 후보 활동 전에 S7의 생성 전체4과정 개요를 간략 재사용.
- 설명용 단계: 문맥 ‘세훈이는’→기존 후보 확률→학생 선택→‘세훈이는 우유를’→그 문맥의 기존 다음 후보.
- 선택 전에는 확률 표와 문맥의 관계를 설명하고, 선택 후 해당 단어가 문장 끝에 들어간 곳을 테두리로 강조한다. “선택한 단어까지 포함한 새 문맥으로 다음 후보를 살펴봅니다.”
- 실제 정의된 milk 분기만 사용한다. TV·버스 선택에 대응하는 새 확률이나 가상 모델 결과를 생성하지 않는다. 현재 낮은 확률 후보 비교는 그대로 남긴다.
- 표 II-13의 빈도 기반 확률 계산과 II-38의 고정 예시 확률을 하나의 계산 결과처럼 합치지 않는다.
- 마지막 설명: “가능성이 큰 단어를 골랐다는 것은 사실이 맞다는 뜻이 아닙니다.” 전체4과정과 후보 반복을 같은 그림의 확대 영역으로 연결한다.
- 다시 보기는 설명 커서만 초기화하며 두 번의 선택·제출·해석 기록을 지우지 않는다.

### 목표 변경 없이 결정한 것

- 완성 풀이·부분 풀이·독립 계산이 이미 충분한 STEP은 다시 늘리지 않는다.

- 공통 레이아웃·Context·라우팅·진행도 구조를 새로 설계하지 않는다.
- 애니메이션 시청·설명 탭 클릭 횟수는 새 필수 조건이 아니다.
- 안내 그림을 보완하되 독립 문제의 정답은 제출 전 공개하지 않는다.

### 별도 제안·미확정 사항

1. **열린 설계 문제의 복수 답 범위:** Lesson01 S3의 최종 특징3개는 지정된 연습 답, S7은 많은 이미지·다층 표현 학습이라는 조건이 붙어 있다. 이를 제한 없는 자유 설계로 바꾸면 정답·저장 답에 영향이 있다. 이번에는 조건을 명확히 하고 현행 판정을 유지한다. 자유 설계 확대는 목표 변경 승인 후 별도 검토한다. Lesson02 목표 출력·Lesson04 허용 은닉층 선택처럼 이미 조건을 만족하는 여러 해를 허용하는 곳은 유지한다.
2. **RNN 문항 자체의 개정 여부:** 현행 state 문자열은 단어별 새 정보 수준이다. 우선 표시 레이블·누적 문맥을 분리하는 V7로 목표를 보완한다. 문항을 누적 상태 해석 문제로 교체하고 저장 답을 바꾸는 안은 이번 확정 범위가 아니다.
3. **원문 표현의 한계:** 교과서 118쪽의 일반 딥러닝/RNN 그림은 순서 처리의 차이를 설명하는 교육용 도식이다. 모든 비RNN 모델이 문맥을 처리하지 못한다는 일반 명제로 확대하지 않는다. RNN이 이중부정을 반드시 맞힌다는 성능 보장도 추가하지 않는다.
4. **실제 화면·접근성·성능:** 본 문서는 소스상 노출 시점과 데이터 연결을 확인한 설계이다. 모바일 줄바꿈, 스크린리더 읽기, 새 강조의 조작감은 미구현·미검증이다. 이후 단계의 대표 표본으로 확인해야 한다.
5. **자료 범위:** 위에 명시한 교과서 본문·그림 및 지도서 과정안을 실제 대조했다. 교과서 전체·지도서 심화 전체를 다시 검토하거나 외부 논문으로 교수법 효과를 검증한 보고서는 아니다.
